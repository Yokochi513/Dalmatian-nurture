# 0014. 当たり判定に Jolt Physics を採用する

- Status: Accepted
- Date: 2026-09-25

## Context

[0012](0012-first-person-controls.md) により、次の当たり判定が必要になった。

- 飼い主（カメラ）と犬が壁・家具・障害物にめり込まないようにする
- 視線の先にある犬や物を判定する（E キーのメニュー用）
- 散歩の広場で障害物にぶつかる

[0006](0006-dependency-libraries.md) では物理演算ライブラリを選定せず、当たり判定が
必要になった時点で自作するか導入するかを決めるとしていた。

## Decision

当たり判定に **Jolt Physics** を採用し、CMake FetchContent で取得する。

これは「ヘッダオンリまたは小規模」という [0006](0006-dependency-libraries.md) の選定基準の
**例外** とする。例外とする理由は次のとおり。

- 移動時のめり込み防止（キャラクターコントローラ）と視線の判定を、実績のある実装に任せられる
- 将来、ボールを投げるなどの物理を使った演出を加える場合にもそのまま対応できる
- 当たり判定の自作は本作で示したい技術（レンダラ・スケルタルアニメーション・育成ロジック）の
  中心ではない

Jolt を直接使う範囲は [0015](0015-physics-target.md) で限定する。

## Consequences

- めり込み防止と視線の判定を自作せずに済む
- 依存の中で最も大きなライブラリとなり、初回ビルドの時間が延びる
- Jolt の世界（剛体の登録・更新）とゲーム側の状態の同期が必要になる
- 当たり判定用の形状（床・壁・家具・障害物）をどこで定義するか（Blender で配置して .glb に
  含めるか、コードやデータファイルで定義するか）は別途決める
- ライセンスは MIT で、再配布に問題はない

## Alternatives considered

- **単純な形状（平面・軸にそろった箱・円柱）で自作する**: 数百行程度で済み単体テストもしやすく、
  0006 の基準にも合うが、将来の物理演出には作り直しが必要になる
- **Bullet Physics**: 実績は長いが、Jolt に比べて設計が古く、ビルドも重い
- **ReactPhysics3D など小規模な物理ライブラリ**: 0006 の基準には近いが、キャラクター
  コントローラなどの機能と利用実績で Jolt に劣る
