# 0022. 閉じていた間の経過は、欲求の変化だけを専用の計算で一括して進める

- Status: Accepted
- Date: 2026-09-25

## Context

[0008](0008-time-progression-hybrid.md) により、アプリを閉じている間も欲求と昼夜は進み、
起動時にセーブの最終終了時刻から経過時間を計算する。

[0021](0021-fixed-one-second-tick.md) の1秒刻みをそのまま使うと、1週間の不在で約60万回の
計算になる。また [0016](0016-care-effect-on-accept.md) により行動の終わりは `app` からの通知で
決まるが、閉じている間は `app` が演出しないため通知が来ない。

## Decision

起動時の経過は、1秒刻みとは別の **不在専用の計算** で一括して進める。

- 欲求の変化だけを経過時間から一度に計算し、[0008](0008-time-progression-hybrid.md) の上限をかける
- 行動意図は進めず、再開時に決め直す
- 不在中に起きた出来事（機嫌が下がった など）は [0020](0020-core-state-read-events-returned.md) の
  戻り値として返し、「おかえり」の表示（[0011](0011-scenes-home-and-walk.md)）に使う
- 以降は1秒刻みで進める

```
起動
  elapsed = now - 最終終了時刻
  欲求 += 変化率 × elapsed（上限で打ち切り）
  行動意図 → 再開時に決め直し
  出来事 → 「おかえり」の表示に使う
```

## Consequences

- 不在がどれだけ長くても、起動時の計算は一瞬で終わる
- 不在中に犬が勝手に行動し続けるような不自然さがない
- 欲求の変化は、経過時間から一度に計算できる式（一定の変化率など）で表す必要がある。
  1秒刻みの結果と不在専用の計算の結果が一致することを単体テストで確かめる
- 時計が戻っていた場合（PCの時計の変更、デバッグ用の時計 [0025](0025-debug-time-controls.md)）は、
  経過時間を0として扱う
- 散歩中に終了した場合の扱いはセーブの設計で決める

## Alternatives considered

- **1秒刻みを経過分すべて繰り返す**: コードの経路は1つで済むが、長い不在で起動が遅くなり、
  不在中の行動意図の扱いを別に決める必要がある
- **上限までの時間だけ1秒刻みで進める**: 計算回数に上限がつくが、不在中の行動意図の扱いは
  やはり必要になる
