# 0007. 3Dアセットは Blender 経由で glTF 2.0 (.glb) に統一する

- Status: Accepted
- Date: 2026-09-25

## Context

ダルメシアンの3Dモデルは、既成アセットの調達と Blender での自作を並行して進める方針である。
つまり入力となるファイル形式が複数（FBX、OBJ、blend など）混在しうる。

育成ゲームとして、歩く・座る・食べる・尻尾を振るといったアニメーションが必須であり、
スケルトンとアニメーションクリップを扱える形式でなければならない。

## Decision

ランタイムが読み込む3Dアセット形式を **glTF 2.0 バイナリ（.glb）に統一** する。

- 既成アセット（FBX等）は Blender にインポートし、.glb としてエクスポートし直す
- 自作モデルも Blender から .glb でエクスポートする
- スケルトン（armature）とアニメーションクリップを .glb に含める
- リポジトリには変換後の .glb と、編集元の .blend を `assets/` 配下に置く

## Consequences

- ランタイム側のローダが1形式のみで済み、cgltf（[0006](0006-dependency-libraries.md)）
  だけで完結する
- Blender が変換の単一経路になるため、既成アセットを使う場合もBlenderの操作は必要になる
- 既成アセットのライセンス確認が必須になる。ポートフォリオとして公開するため、
  再配布可否をアセットごとに記録する
- .glb と .blend はバイナリのためGitの差分が効かず、リポジトリサイズが増加する。
  サイズが問題になった時点で Git LFS 導入を新しいADRとして検討する

## Alternatives considered

- **FBX を直接読み込む**: 仕様が公開されておらず、自作ローダの実装コストが高い
- **OBJ**: 静的メッシュのみでスケルタルアニメーションを表現できないため、育成ゲームに使えない
- **独自の中間形式に変換するツールを自作**: 起動が速くなる利点はあるが、
  現時点では最適化の前倒しであり、必要になってから検討する
