# 0017. 世話の可否は core が理由付きで返し、実行できない項目もメニューに表示する

- Status: Accepted
- Date: 2026-09-25

## Context

[0012](0012-first-person-controls.md) により、世話は視線の先の対象に対するメニューから選ぶ。
[0008](0008-time-progression-hybrid.md) により、世話にはクールダウンや1日あたりの上限があり、
実行できない場面がある。

餌皿やリードといった物は空間の中にあり、`core` は知らない（[0009](0009-module-structure.md)）。
メニューの項目を誰が決め、実行できない世話をどう見せるかを決める必要がある。

## Decision

- 物と世話の対応（餌皿 → ごはん、犬 → なでる・しつける・遊ぶ など）は **`app` が持つ**
- 各世話を実行できるかどうかは **`core` に問い合わせる**。`core` は可否に加えて、
  **理由**（クールダウン中・今日の上限・寝ている など）と **残り時間** を返す
- メニューには実行できない項目も表示し、理由を添えて薄く表示する

```
┌─ ポチ ─────────────────┐
│ なでる                   │
│ しつける（あと15分）      │ ← 薄く表示
│ 遊ぶ（今日はもう満足）    │ ← 薄く表示
└─────────────────────────┘
```

## Consequences

- プレイヤーがクールダウンや1日の上限という仕組みを理解でき、「押しても何も起きない」
  状態を避けられる
- 可否の判定が `core` に集まり、単体テストで確認できる
- 理由の種類を `core` と `app` で共有する必要があり、表示する文言への変換は `app` が行う
- 実行時にも `core` は同じ判定を行い、実行できない命令は拒否する

## Alternatives considered

- **実行できる項目だけを表示する**: メニューはすっきりするが、なぜ選べないのかが
  プレイヤーに分からない
- **常に全項目を表示し、実行時に断る**: 犬がそっぽを向くなどの反応で犬らしさは出るが、
  理由が伝わりにくく、断ったときの演出が別途必要になる
