# 0016. 世話の効果は受け付けた時点で確定し、演出の終了は app が通知する

- Status: Accepted
- Date: 2026-09-25

## Context

[0009](0009-module-structure.md) により、`core` は犬の行動意図までを決め、アニメーションと
移動は `app` が担う。世話（ごはんなど）は「餌皿に入れる → 犬が歩いていく → 食べる」のように
演出に時間がかかるが、その長さは空間（距離や当たり判定）に依存するため `core` には分からない。

世話の効果（欲求の回復・しつけの実績など）をどの時点で `core` の状態に反映するかを決める
必要がある。

## Decision

- `core` は世話の命令を受け付けた時点で **効果を確定** し、行動意図を世話に対応するもの
  （Eat など）に切り替える
- `app` は演出が終わったら `core` に **行動の終了だけを通知** する
- `core` は終了の通知を受けて、次の行動意図を決める

```
app  → core : ごはんをあげる
core        : 受付 → 空腹を回復、意図 = Eat
app         : 皿へ歩く → 食べる演出
app  → core : 行動が終わった
core        : 次の意図を決める
```

## Consequences

- 効果の計算が演出に左右されず、`core` の単体テストは命令と状態の検証だけで済む
- 演出が途中で中断されても（シーン切り替え・終了など）、効果は失われない
- ゲージは演出より先に回復する。違和感がある場合は、UI側で表示値をゆっくり追従させる
- `app` が終了の通知を忘れると、犬が同じ行動意図のまま止まる。`core` 側に行動意図ごとの
  最大継続時間を設けるなどの保険を検討する

## Alternatives considered

- **演出が終わった時点で効果を確定する**: 見た目と数値が一致するが、効果を保留している間の
  状態と、途中で中断したときの扱いが `core` に必要になる
- **効果も行動の長さもすべて `core` が決める**: `core` から `app` への一方向で最も単純だが、
  歩く距離によって変わる演出の長さに合わせられない
