# 0003. ゲームエンジンを使わずC++と小規模ライブラリで実装する

- Status: Accepted
- Date: 2026-09-25

## Context

Unity / Unreal / Godot といった既成エンジンを使えば、プレイ可能な状態までの距離は
大幅に短くなる。一方、本プロジェクトの目的はポートフォリオとしての公開であり、
低レイヤの実装力を示すこと自体に価値がある。

なお開発者のC++習熟度は「文法は理解しているが大規模なコードベースの経験はない」段階である。

## Decision

ゲームエンジンを使用せず、**C++20 と小規模ライブラリの組み合わせ** で実装する。

自作する範囲と外部に任せる範囲を以下のとおり線引きする。

| 自作する | 外部ライブラリに任せる |
|---|---|
| レンダリングパイプライン | ウィンドウ生成・入力 |
| シーン管理 | 行列・ベクトル演算 |
| スケルタルアニメーション再生 | glTFのパース |
| 育成ロジック（ステータス・時間経過） | デバッグUI描画 |
| セーブ／ロード処理 | 音声再生 |

具体的なライブラリ選定は [0006](0006-dependency-libraries.md) で扱う。

## Consequences

- レンダラとスキニングを自作するため、低レイヤの実装力を成果物として示せる
- 「犬が歩いて餌を食べる」状態に到達するまでの工数がエンジン利用時の数倍になる。
  最大の山場は **glTFのスキンデータからジョイント行列を構築し、頂点シェーダで
  スキニングを行う部分** である
- エンジンが提供する当たり判定・パーティクル・シーンエディタは存在しない前提で
  ゲーム内容を設計する必要がある
- 大規模経験の不足を補うため、育成ロジックは描画に依存しない純粋なC++として分離し、
  単体テスト可能に保つ（[0005](0005-build-system-cmake-msvc-cpp20.md)）

## Alternatives considered

- **Unity / Godot / Unreal**: プレイ可能までは最短だが、示せるのはエンジンの
  習熟度であり、本プロジェクトの狙いと合わない
- **bgfx / raylib などの描画補助ライブラリ**: 3Dの土台を短縮できるが、
  「レンダラを自作した」という価値が薄まる
- **完全自作（Win32 API直叩き・自前の数学ライブラリ・自前glTFパーサ）**:
  学習価値は最大だが、プレイ可能な状態に到達できないリスクが高い
