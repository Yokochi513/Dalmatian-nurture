# 0019. 行動意図は行き先の種類だけを持ち、座標は app がシーンの地点表から決める

- Status: Accepted
- Date: 2026-09-25

## Context

犬の行動（ごはんを食べる・寝床で寝る・うろうろする）には行き先が必要である。
一方で [0009](0009-module-structure.md) により、`core` は描画も空間も知らない。

## Decision

- `core` の行動意図は、**行き先の種類**（Bowl：餌皿、Bed：寝床、Any：どこか など）を持つ
- `app` はシーンごとに **名前付きの地点の表** を持ち、行き先の種類を座標に変換して、
  `physics` を使って犬を移動させる

```
core : 意図 = Eat,    行き先 = Bowl
core : 意図 = Sleep,  行き先 = Bed
core : 意図 = Wander, 行き先 = Any
app  : シーンの地点表 { Bowl: (x, z), Bed: (x, z), ... }
       → physics で移動
```

## Consequences

- `core` は空間を知らないまま、行動と行き先の対応を単体テストで確かめられる
- 地点の配置はシーンのデータであり、コードを変えずに調整できる
- 地点の定義場所（Blender で空のオブジェクトとして配置し .glb から読むか、別のデータファイルに
  書くか）は、当たり判定用の形状の定義場所（[0014](0014-physics-jolt.md)）と合わせて決める
- シーンに存在しない行き先の種類が指定された場合（散歩中に Bed など）の扱いを `app` で決める
  必要がある

## Alternatives considered

- **行き先はすべて `app` が決める**: `core` はさらに単純になるが、行動の意味と場所の対応が
  `app` のコードに散らばり、テストで確かめにくい
- **`core` が座標まで持つ**: 距離に応じた判断などもできるが、`core` は空間を知らないという
  [0009](0009-module-structure.md) の方針に反し、当たり判定との同期も必要になる
