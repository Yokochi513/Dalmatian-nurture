# 0041. モジュール内部の決定は docs/module_design/ に記録し、ADR はモジュールをまたぐ決定に使う

- Status: Partially superseded by [0043](0043-module-design-per-component.md)（設計書のファイルの単位）
- Date: 2026-09-26

## Context

[0001](0001-record-decisions-in-adr.md) と AGENT.md により、決定事項は1件ずつADRとして記録している。
モジュールをまたぐ決定（依存の向き・やり取りの形・セーブの運用など）がそろい、各モジュールの内部設計
（時計の型・欲求の計算式・構造体のメンバーなど）に入った。内部設計の決定は数が多く、互いに密接に
関係するため、1件ずつADRにすると分散して全体像を読み取りにくい。

## Decision

- **ADR**：複数のモジュールにまたがる決定、またはプロジェクト全体の方針
- **`docs/module_design/<モジュール名>.md`**：1つのモジュールの内部の決定（型・関数の形・計算の規則・
  ファイル構成など）。モジュールごとに1ファイルとし、設計が進むたびに更新する
- 設計書で決めた内容がほかのモジュールに影響する場合は、ADRにする

AGENT.md のルールにも、この分け方を追記する。

## Consequences

- モジュールの内部設計を1か所で通して読める
- 設計書は書き換えるため、ADRと違って過去の判断の経緯は Git の履歴で追うことになる
- 内部の決定か、モジュールをまたぐ決定かの判断が必要になる。迷った場合はADRにする

## Alternatives considered

- **内部の決定もすべてADRにする**: 経緯は最も追いやすいが、ADRの数が大きく増え、1つのモジュールの設計が
  多数のファイルに分散する
- **設計書だけにする（ADRをやめる）**: 記録先は1つになるが、モジュールをまたぐ決定の経緯が上書きで失われる
