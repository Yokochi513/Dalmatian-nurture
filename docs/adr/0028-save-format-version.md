# 0028. セーブに形式の番号を持たせ、公開後は古い形式から1段ずつ変換する

- Status: Accepted
- Date: 2026-09-25

## Context

開発を進めると、欲求の種類や芸が増え、セーブの形式が変わっていく。公開後に形式が変わると、
遊んでいる人の犬が読み込めなくなるおそれがある。一方、公開前は形式が頻繁に変わるため、
変更のたびに変換を書くのは手間が大きい。

## Decision

- セーブに **形式の番号**（`"version"`）を持たせる
- **公開前** は、番号が現在の形式と合わなければ、古いファイルを退避して新しく始める
  （退避の方法は [0027](0027-save-atomic-write-and-backup.md) と同じ）
- **公開後** は、形式を変えるたびに1段分の変換（v1→v2、v2→v3 …）を `core` の `save` に足し、
  古いセーブを順に変換して読み込む
- 変換は、古い形式の見本ファイル（例：`tests/core/saves/v1.json`）を使って単体テストで確かめる

## Consequences

- 開発中は形式を自由に変えられ、公開後は遊んでいる人の犬を守れる
- 変換は1段ずつなので、どれだけ古いセーブも順にたどれば読み込める
- 公開の時点で番号の運用を切り替える必要がある。切り替えを忘れないよう、公開の手順に含める
- 公開前に自分で育てた開発用の犬は、形式が変わると失われる

## Alternatives considered

- **番号を持たせ、最初から順に変換する**: 開発用のセーブも守れるが、形式が頻繁に変わる時期に
  変換を書く手間がかかる
- **番号を持たせず、足りない項目は初期値で埋める**: 項目の追加には強いが、名前や意味が
  変わったときに気付かないまま誤った値で読み込まれる
