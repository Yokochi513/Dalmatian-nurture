# 0043. モジュール設計書は、概要と、ソースファイルに対応する部品ごとのファイルに分ける

- Status: Accepted
- Date: 2026-09-26

## Context

[0041](0041-module-design-docs.md) で、モジュール内部の決定を `docs/module_design/<モジュール名>.md` に
1ファイルで記録すると決めた。core の設計を進めると、時計・犬の状態・欲求・世話・時間の進め方が1ファイルに
並び、今後も成長・芸・行動意図・セーブが加わるため、1ファイルが長くなり、部品ごとに読みにくくなった。

## Decision

- `docs/module_design/<モジュール名>.md`：モジュールの **概要**（責務・設計の方針・部品と設計書の一覧・
  テスト方針）
- `docs/module_design/<モジュール名>/<部品名>.md`：**部品ごとの設計**。部品はソースファイルの単位
  （例：`src/core/care.hpp/.cpp` → `docs/module_design/core/care.md`）に対応させる
- バランスの数値のように複数の部品で共有するものは、それを使う部品の設計書に書く

本ADRは [0041](0041-module-design-docs.md) のうち、設計書のファイルの単位の部分を置き換える。

## Consequences

- 部品を設計・実装するときに読む設計書が1つに絞られる
- ソースファイルと設計書の対応が明確になる
- 部品をまたぐ内容（`DogState` のメンバーなど）は、複数の設計書から参照することになる
- ファイルが増えるため、概要の一覧を最新に保つ必要がある

## Alternatives considered

- **モジュールごとに1ファイルのまま**: ファイルは少ないが、長くなって読みにくい
- **世話だけを別ファイルにする**: 変更は少ないが、部品によって置き場所がばらばらになる
